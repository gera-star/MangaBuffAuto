# MangaBuffAuto V10.4 — Automation Expansion

Основа: рабочий V10.3 + анализ предоставленного `MangaBuffAutoDaily-1.5.0`.

## Что добавлено/исправлено

### Архитектура задач
- Добавлен `TaskManager`.
- Один активный `TaskExecution` за раз.
- Каждый запуск получает новый UUID `runId`.
- Результаты JS принимаются только при совпадении `taskId + runId`; для защитных JS-событий дополнительно проверяется `docId`.
- Очереди и автоматических цепочек между независимыми кнопками нет.

### ⛏️ MineTask
Использованы только селекторы, найденные в исходнике AutoDaily 1.5.0:
- `button.main-mine__game-tap`
- `.main-mine__game-hits-left`
- `button.mine-shop__upgrade-btn`
- `button.mine-shop__ore-change-btn`

В текущей версии выполняется безопасный основной сбор ударов и остановка по доступному лимиту ударов. Автоапгрейд/автообмен пока не включены в UI: для них требуется отдельная проверка актуального DOM и правил сайта перед автоматическим действием.

### 📺 WatchAdsTask
Подтверждены исходником AutoDaily:
- `/balance`
- `button.button--primary.user-quest__watch-ads-btn`
- `div[data-fullscreen-element-name='close-btn']`

Убрано координатное угадывание крестика. Сначала используется реальный DOM close-контрол, затем ограниченный fallback по aria-label/title. Фиксированное преждевременное закрытие рекламы не используется: задача ждёт реальный close-контрол.

### 💎 ChatDiamondTask
Использован подтверждённый в AutoDaily DOM-элемент:
- `button.chat-arena__get-coins-btn`

Это одноразовая DOM-задача. Сетевой запрос к `mc.yandex.ru/clmap/...` из старого AutoDaily не копируется.

### 👤 Multi-Profile
Существующий AndroidX WebView Multi-Profile сохранён:
- отдельные cookies/WebStorage для каждого профиля;
- переключение только когда активной задачи нет;
- пароли приложение не хранит.

### 📖 Reader
`ReadTask` не изменён. Фоновое чтение, native heartbeat, скорость 1x/2x и логика окончания манги сохранены из V10.3.

### 🛡️ Безопасность
Не добавлены:
- обход CAPTCHA/Cloudflare;
- fingerprint spoofing;
- User-Agent spoofing;
- proxy/IP rotation;
- скрытие автоматизации;
- автоматический обход блокировок.

При CAPTCHA/блокировке автоматизация останавливается.

## Что сознательно оставлено TODO

### QuizTask
`.quiz__answer-item.button` подтверждён AutoDaily, но его Selenium-версия получает `question.correct_text` через DevTools Network. Аналогичный надёжный перехват response body в нашем WebView пока не подтверждён. Поэтому Quiz не включён в UI и расписание.

### Автокомментарии
AutoDaily умеет планировать комментарии, но эта функция требует отдельной проверки актуального DOM/API и отдельной политики частоты. Она не включена автоматически.

### Автоапгрейд/автообмен шахты
Селекторы известны из AutoDaily, но перед включением нужно проверить текущие состояния кнопок и подтверждение операции на актуальном сайте.

### Планировщик
V10.4 не запускает скрытый бесконечный scheduler. Автоматические задачи остаются явными действиями пользователя, чтобы не было неожиданных запусков после перезапуска приложения.

## Проверки перед упаковкой
- Kotlin-файлы задач (`AutomationTask`, `TaskExecution`, `TaskResult`, `TaskManager`, Mine, Ads, Chat, Quiz) компилируются standalone через `kotlinc`.
- Проверена целостность исходного проекта и ZIP.
- Полный Android Gradle build в среде подготовки не выполнен: Gradle Wrapper 9.6.0 требует загрузки `services.gradle.org`, а DNS/сетевой доступ к нему недоступен. Поэтому не утверждается, что полный APK был собран в этой среде.
